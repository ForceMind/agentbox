# Fixed Noise NX software core

Status: merged in PR #65 as `f95d1a4b0f0bdbdda45bd8da6cc10f3f8ac10269`, after independent review and 19/19 successful exact-head CI checks.
This is a cryptographic core, not an admitted AgentBox terminal channel.

## Scope and boundaries

The Python module `agentbox_protocol.noise_nx` and browser module
`apps/web/src/features/workspace/noiseNx.ts` implement only the fixed
`Noise_NX_25519_AESGCM_SHA256` profile from [Noise revision 34](https://noiseprotocol.org/noise.html).
They implement the two NX handshake messages and the split send/receive cipher
states using existing Python `cryptography==50.0.0` and native WebCrypto. No
cryptographic dependency or alternate pattern has been added.

The caller supplies validated prologue bytes and, for the Runtime role, its
trusted static key. Default ephemeral keys are generated by the platform CSPRNG.
Deterministic key injection is tested only with the published public vector.
The core does not discover files, read a real private key, execute a vendor CLI,
open a socket or grant an attachment. It exposes the handshake hash and remote
static public key as public evidence for the future trust-pin verifier; a
successful NX exchange alone is not application authorization.

## State and failure rules

- Each handshake message is generated/consumed once in its fixed order. Split
  transport is transferred once; handshake references are then discarded.
- CipherState owns its counter. It starts at zero, advances after successful
  cryptographic operations and cannot be set by a caller. AES-GCM uses the Noise
  nonce construction; the reserved maximum counter is rejected.
- Plaintext is at most 65,519 bytes, ciphertext is 16–65,535 bytes and associated
  data is bounded. Application WAW limits remain stricter and are not enabled here.
- Invalid state/type/length, failed authentication and exhausted counters close
  the relevant state. No nonce skip, replay retry, downgrade or plaintext fallback
  exists. Python operations serialize with locks; browser operations are bounded
  and reject concurrent calls instead of accumulating a payload queue.
- Destroy discards state/key references and prevents later use. Managed Python
  and WebCrypto runtimes do not provide a claim of physical heap zeroization.
  The implementation must reject any late async result after destroy.

## Independent evidence

The shared [public Noise-C fixture](../tests/fixtures/noise_nx/NOTICE.md) records
its pinned source commit, full-source SHA-256, extracted-fixture SHA-256 and MIT
copyright/license text. Its known private keys are public test material, never
host identity keys. Tests compare exact raw handshake messages, final hash and
four alternating transport ciphertexts, not just two peers implemented here.

`scripts/check-noise-interop.mjs` transpiles the actual TypeScript source into a
temporary module and runs a bounded Python test peer through captured pipes. It
checks WebCrypto-initiator/Python-responder and the reverse roles, both handshake
messages, the final hash, all four transport vectors, nonempty associated data,
bidirectional application-sized samples and tamper/closed-state behavior. The
script prints bounded pass/fail metadata; it does not log plaintext or keys.
Temporary transpiled source is removed. Frontend CI runs this check with Node 22
and Python 3.13 in addition to its usual tests/build.

Test/CI counts and review results are recorded in
[CURRENT_STATE.md](project/CURRENT_STATE.md). Unit tests, Node WebCrypto and CI
are distinct from native browser/host validation.

## Remaining application integration

The existing WAW architecture does not freeze three exact wire definitions:
`protocol_id`, `transcript_context_hash` and direction-label/AAD concatenation.
The [concrete supplemental proposal](project/WAW_ENCRYPTED_STREAM_DECISION.md)
is pending Owner decision. This core neither chooses those bytes nor declares
the historical architecture proposal accepted.

Still required: signed Runtime pin trust, confirmation/ACK application profile,
AWCE context/envelope validation, API ciphertext-only admission/relay, Runtime
stream socket composition, browser terminal integration, exact disconnect cleanup
and real CLI/PTY/Linux qualification. The production WebSocket route remains
fail closed until its complete authorized implementation and evidence are ready.

## Native Chromium verification

`apps/web/e2e/noise-core.spec.ts` compiles the actual TypeScript source into the
browser page and invokes native `window.crypto.subtle` in a secure localhost
context. The runner uses Node only to prepare published fixture key encodings;
Node WebCrypto is not substituted for the browser implementation. The test
compares both handshake messages, four transport ciphertexts and both handshake
hashes against the same pinned fixture, checks private-key nonextractability,
exercises nonempty AD in both directions and rejects tamper followed by the
original valid ciphertext at the same counter. Trace, video and screenshots are
explicitly disabled; only bounded result markers and browser-version metadata
are reported. Cipher/handshake references are destroyed after the checks.

Local Chromium `151.0.7922.34` passed the `desktop-chromium` and
`mobile-chromium` profiles. The full isolated harness run containing these tests
returned exit 1: 56 passed, 4 existing authentication waits timed out at 5 seconds.
Both new crypto cases passed. The failures were three Dashboard-after-login
waits and one invalid-credentials alert wait; they occurred before those tests'
subsequent business assertions. No assertion or timeout was relaxed. These are
observed local failures, not a proven new runtime regression or a full local E2E
PASS. The supported Linux CI runs the complete updated suite as the merge gate.
Mobile here is a Chromium device profile, not physical-device/IME qualification.
The harness stopped its temporary API/preview and removed its temporary data.
