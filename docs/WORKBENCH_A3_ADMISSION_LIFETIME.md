## Inert boundary and actual owners

No production entrypoint imports the new API/Runtime adapters. The existing
lifecycle owns a dormant optional selector slot; only the explicit test
composition calls its replacement method. There is no new
HTTP/WebSocket/RPC route, socket, host activation, real key loader/generator, pin
enrollment, UI or release. `A3TestReadOwner` and `A3OpaqueTestRelay` default to
closed; construction requires the explicit `enabled_for_tests=True` fixture
argument. It is not a deployment setting or an authorization mechanism. The
only new key port is exact-type `A3SyntheticTestKey` for published synthetic
A3 fixture bytes. WAW Runtime key ports and keys are not reused.

`A3SessionCurrentness` reads the existing Control Plane database. Its constructor
extracts session ID, user ID and auth epoch from an already authenticated API
session and does not retain `AuthenticatedSession` (which contains CSRF).
Read-only validation checks the current session/user association, active user,
revocation, current auth epoch, the existing persisted absolute and idle expiry policy
and clock regression. It never calls `authenticate` again or updates
last-seen. The SHA256 domain-separated session-scope commitment changes with
session/user/auth epoch and is noncredential metadata, never bearer authority.
The typed cross-boundary snapshot contains only full Project/binding/host/epoch
facts, scope and auth epoch; no session ID, username, cookie, CSRF or secret.

The same transaction requires one CURRENT binding, READY unarchived Project,
exact Project revision/relative key and current host revision/last Runtime epoch.
A trusted API epoch observation must match it. Runtime independently compares
these facts to `WAWSupervisorExecutor.content_project_binding`, which copies the
existing full binding under its map lock and refuses reserved/inflight/quarantine
or ambiguous duplicate-relative-key states. No second Project registry exists.
The WAW-start exception in the older relative-key resolver is not reused.

The existing `WAWLifecycleRegistry` owns one optional A3 selector slot. Its check
requires the same registered full binding, current Runtime/host epoch, open
application gate, completed binding inventory/replay, no mutation/shutdown/
quarantine and the same currently valid authenticated API process authority.
No Workspace, Agent, attachment or WAW frame identity is an A3 content identity.
Replacement first closes the old selector authority and every active admitted
handle; the old key is invalidated and its original nonce ledger is never reset
for reuse. Shutdown and peer-authority cleanup also close the slot. This adds
no global singleton framework or additional mapping authority.

API/Runtime adapters are exercised together inside synthetic test processes.
The peer currentness fixture is explicitly not real pidfd/host evidence, and the
synthetic binding digest is not real installer provenance. Actual network
serialization/authentication and deployment composition remain separate gates.

## Exact crypto v2 profile

Only the already reviewed NX primitives are reused, unchanged:

- key `protocol_id` is `agentbox-a3-content/crypto/v2`, integer version `2`
- opaque record domain is `agentbox-a3-content/record/v2`
- prologue is ASCII `agentbox-a3-content/noise-prologue/v2`, one NUL byte, then
  exact unchanged canonical v1 `context_bytes` / `contextBytes`
- NX message 2 is exactly 132 bytes; its authenticated payload is fresh
  challenge32 followed by uint32 big-endian `remaining_ms` (36 bytes total)
- confirmation domain is `agentbox-a3-content/noise-confirm/v2`; its digest
  preserves domain || uint32be(32) || challenge32 || full final Noise hash
- ACK is SHA256 of `agentbox-a3-content/noise-confirm-ack/v2`; independent pin
  verification, full transcript equality and directional n=0 confirmation remain
- all v1 crypto IDs/versions/prologues/records and message2 length128 are refused;
  there is no fallback. Plaintext v1 context, records and AAD are unchanged

The final handshake hash includes the complete authenticated lifetime payload,
so the existing confirmation commits to it without a new signing credential or
primitive. `crypto-v2.json` is generated by the separate public PyCA/Noise-C test
oracle and compared byte-for-byte in both languages; retained `crypto-v1.json`
is historical evidence, not an accepted profile.

## Cross-origin monotonic time, without renewal

Runtime retains the ORIGINAL authenticated selector expiry in nanoseconds.
Immediately before calling the unchanged `write_message2(payload)` it samples
Runtime `now_ns` and computes `(original_expiry_ns - now_ns) // 1_000_000`.
Only 1..30000 is valid. Sub-millisecond/zero/negative/oversize is refused, never
rounded up or clamped; separately flooring the two endpoints is forbidden.
Runtime checks the original expiry before/after crypto and every actual send,
including after scheduling and backpressure. The original five-second handshake
cap includes actual ACK publication and is never renewed.

Browser captures ONE local monotonic anchor before INIT generation/publication.
After authenticated payload and independent Runtime pin verification, it sets
`deadline = min(existing_local_cap, anchor + remaining_ms)`, tightens ContentRead
in place without resetting its transcript, and immediately checks before CONFIRM.
All later asynchronous crypto/hash returns retain live/deadline checks. Duplicate
or late messages close instead of extending the deadline. Runtime absolute
monotonic timestamps are never copied into Web.

For trusted progressing elapsed clocks with compatible rates, let browser INIT
anchor occur at physical time a, Runtime budget sample at s, and original expiry
at E. Causality gives s >= a; then a + floor(E-s) <= E. Different clock origins,
asymmetric RTT and later DH/encryption delays only consume this fixed budget.
Sampling before the existing NX call is conservative; no primitive callback is
needed. This is NOT arbitrary clock-rate/skew resistance or a guarantee for a
suspend-paused browser clock. Self-reported skew is not authority. Owners must
close on visibility/lifecycle/freeze/disconnect; the inert Web role exposes an
explicit interruption method but installs no DOM or network handlers.

The Runtime owner rechecks pending I/O every 50 ms (event-loop scheduling and
synchronous currentness work can delay that polling); it still checks immediately
before actual publication without an intervening await. There is no new grace
period or lifetime extension. Cancellation/authority loss closes pending I/O,
handles and profile; nonce burns remain valid through original expiry.

## Bounds, failures and evidence

Whole PAGE plaintext remains <=16 KiB, <=16 pages; opaque frames remain <=24 KiB.
The selector owner retains the original shared four-active limit and 128 nonce
ledger. API test relay retains one whole record per direction and one sender/
receiver owner per direction, closes on concurrent ownership, oversized input,
loss, cancellation or uncertain publication, and cannot be reopened. No plaintext
accessor, debug/log/Audit payload, persistent patch cache or generic gateway exists.
Only complete END validation can yield patch bytes; no partial output is success.

Tests cover real existing API session/READY rows, no credential crossing, epoch,
revocation/expiry, binding/host/peer/gate/inflight/quarantine/replacement, pending
idle loss, late replies and one-owner nonce behavior. Crypto cases cover literal
v2 vectors, old-profile refusal, fractional-nanosecond floor edges, authenticated
invalid budgets, cross-origin/asymmetric delay, crypto-expiry, no reset, finalhash
lifetime binding and exact capacity. The native Git→admitted owner→opaque pipe→Web
harness now uses the real API adapter over synthetic application fixtures and an
independent browser time origin; loss/tamper/visibility yield no partial bytes.

This is source/fixture/software evidence only. Final local checks and new
exact-head CI are recorded in [current state](project/CURRENT_STATE.md).
Production credentials, host/device qualification, pin distribution, transport
activation, deliberate diff UI and deployment/support claims remain unperformed.
