# AgentBox 0.3.0rc30 — fixed Runtime vendor enrollment input

The R12 authority-deferred Runtime provider no longer accepts only an
unbound map of version strings and a Codex output digest. It now requires a
fixed, installer-owned, non-secret enrollment observation. The Runtime
reader validates the sole installed path, exact account, parent and file
provenance, bounded canonical JSON and the required fields. Before any
executable, policy or cgroup resource opens, the provider compares host,
manifest and enrollment pins with the builder's one verified authority and
re-reads the installed record. A missing or changed file fails closed.

This is a software input/source contract, not a real enrollment. The
installer does not yet create the file with target observations; production
`_main`, the positive legacy Codex Remote conflict source, and the real
host/client/CLI gates remain unfinished. The
[contract](../WAW_R12_VENDOR_ENROLLMENT.md) records the fixed format and
remaining dependencies. Python, npm and inert MV3 versions map to
`0.3.0rc30`, `0.3.0-rc.30` and `0.3.0.30`. Validation and exact-head CI
evidence are recorded in [CURRENT_STATE](../project/CURRENT_STATE.md).
Local Runtime/auth/application/release tests passed 184 cases, Linux-target
mypy checked 317 files, and Ruff passed. AppShell version tests passed four
cases; Web format/lint/build and inert MV3 tests/build passed. The isolated
desktop/mobile Chromium matrix passed 112 cases with 28 prescribed skips;
this checks the existing UI and visible version on the earlier candidate,
not the uninstalled Runtime file reader. The rc30 merge resolution requires
fresh relevant tests and exact-head CI; independent review remains pending.
