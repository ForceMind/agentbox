# AgentBox 0.3.0rc26 — Workspace label assignments

The authenticated Workspace page can assign the existing per-administrator
navigation labels to the selected formal Project/AgentType identity. Assignment
metadata remains in the Control Plane and can be set before the Runtime has
ever started a terminal. It never grants Workspace execution or file access.
The browser waits for the exact revision acknowledgment and a fresh catalog
and assignment read before it displays a change. Session/selection/visibility
changes invalidate pending observations.

The additive `0012_workspace_labels` migration stores one ordered label set
per `(admin_user_id, project_id, agent_type)` with a separate monotonic
revision. The new authenticated `GET`/Origin+CSRF `PUT` routes use the same
immutable catalog IDs. Deleting a catalog definition now requires explicit
confirmation of both affected Project and Workspace counts and rechecks both
inside one transaction; deleting it bumps every affected set revision. An
older client lacking the Workspace count fails closed at request validation,
so API and Web need a coordinated upgrade.
