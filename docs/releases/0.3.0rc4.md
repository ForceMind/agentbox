# AgentBox 0.3.0rc4 — browser trust and terminal development candidate

Planned release display/tag: `v0.3.0-rc.4`. This source increment does not create
the tag, publish a GitHub Release, install a browser extension, activate a host or
inherit the real-host qualification recorded for `0.3.0rc1`.

## Included software

- Strict public bootstrap/root/pin parsing, Ed25519 lifecycle verification,
  rollback/time floors and generation-bound provider invalidation leases.
- Managed Chromium external-port and Native Messaging protocols, an independent
  `trustd` store/session authority and a public-only deployment bundle builder.
  The ordinary extension build is externally inert until deployment enrollment.
- A bounded Unicode 13 terminal model with closed bidi/default-ignorable,
  Hangul and emoji rules, cooperative model/projection/render tasks and fixed
  one-second CPU accounting.
- Browser-first-language selection between `zh-CN` and English, document `lang`
  initialization and bilingual Workspace lifecycle copy.

## Verification boundary

Tests use the unchanged public 2030 trust vectors, synthetic policy stores,
fake Chrome runtime ports and deterministic clocks. They do not install a CRX,
mutate a browser policy, use a real trustd OS identity or handle terminal payload
from a provider CLI. Independent review and exact-head CI/merge evidence are
recorded in `docs/project/CURRENT_STATE.md` only after they occur.

## Not included

- A real CRX signing key, extension ID, update channel, deployment Origin,
  installed Native Host/trustd service or client policy. These remain R12 inputs.
- Hardware-backed monotonic time or resistance to a privileged consistent
  rollback of the whole trustd store while an older pin remains time-valid.
  R12 must qualify that deployment boundary.
- Browser attachment/controller and fixed interactive Claude/Codex process
  composition, which remain R10/R11 work.
- Full bilingual migration of non-Workspace pages, scheduled for R11 before
  product qualification.
