# AgentBox 0.3.0rc1 — MVP Release Candidate

Planned release display/tag: `v0.3.0-rc.1`. Phase 10 prepares this material but
does not create the tag or publish a GitHub Release.

## What AgentBox is

AgentBox is a pre-release, single-server, single-administrator Linux x86_64
control plane for a user-owned AI development workstation. The default API/Web
listener is loopback-only and the browser-facing services run without root.

## Included in this candidate

- Secure authenticated control plane with local admin bootstrap, Argon2id,
  Session/CSRF controls, persistent bounded login limiting, and sanitized
  diagnostics.
- Codex public-capability detection, Remote start/stop management, and an
  ephemeral Pair Code channel that does not enter normal persistence or logs.
- Claude Code project Sessions managed through an isolated Runtime identity and
  exact marked tmux sessions, with manual Workspace Trust guidance.
- Formal Project Workspaces, safe create/clone, structured Git status, ordinary
  branch operations, fast-forward-only Pull, no-force Push, and Draft PRs.
- Native installer, distinct API/Worker/Runtime identities, hardened systemd
  units, minimal typed root Helper, FHS paths, production SQLite, and prebuilt
  static Web assets.
- Staged upgrade, online WAL-consistent backup, verified rollback, bounded
  retention, and data-preserving uninstall.
- Threat-driven security hardening, strict IPC parsing/peer checks, dependency
  audits, platform fixtures, Doctor/status diagnostics, and release artifacts
  with manifest/SBOM/SHA-256 integrity metadata.

## Not included

- Provider Manager, Secret Manager, RuntimeBindingID, Provider switching, or
  automatic Provider failover.
- Multi-server or multi-user SaaS operation.
- Browser terminal, arbitrary shell, destructive Git actions, or Project file
  deletion.
- Public listener, TLS termination, SSH/firewall/tunnel automation, Kubernetes,
  or Docker management.
- Artifact signatures, publisher provenance attestation, tag, or published
  GitHub Release in this preparation PR.

## Installation prerequisites

- A reviewed platform above, systemd, and root authority for installation.
- Python 3.11–3.13 with `venv`; the artifact manifest declares
  `>=3.11,<3.14` and ABIs cp311/cp312/cp313. `install.sh` rejects Python 3.10
  and 3.14 before creating a venv or running pip. The artifact includes the
  pinned Linux x86_64 wheelhouse and prebuilt Web files.
- Git/curl/SQLite and the fixed packages shown in the installer plan.
- Node is not required for AgentBox API/Web production operation. Claude/Node,
  Codex, tmux, bubblewrap, and gh are optional Runtime integrations and report
  their actual unavailable/unauthenticated state.

Follow [Quickstart](../QUICKSTART.md). Always verify `SHA256SUMS`, then run the
bundled verifier and read the install plan. SHA-256 is integrity evidence only;
this candidate is unsigned.

## Post-install manual steps

1. Run local `agentbox admin init`; no default password exists.
2. Configure operator-managed HTTPS remote access and exact trusted
   proxy/origin settings while retaining Secure Cookies.
3. As `agentbox-runtime`, complete official Codex login/pair, Claude login, and
   `gh auth login` flows as needed.
4. Run `agentbox status` and `agentbox doctor`.

Never copy or chown root Codex, Claude, or gh credential directories.

## Upgrade and rollback

Review the update plan, preserve the verified online SQLite/config/unit backup,
stage the new immutable release, run explicit migration, activate, and require
health/readiness/version checks. Rollback is successful only when the prior
release, database revision/integrity, services, sockets, endpoints, and version
all verify. See [Upgrade](../UPGRADE.md) and [Rollback](../ROLLBACK.md).

## Security notes

- API, Worker, and Runtime remain non-root; the socket-activated Helper exposes
  six fixed AgentBox lifecycle actions only.
- Pair Codes, passwords, Sessions, CSRF values, application secrets, Runtime
  credentials, and Git credentials are excluded from artifacts and ordinary
  persistence/output.
- Production browser authentication still requires HTTPS through an explicitly
  trusted operator-managed proxy/tunnel. Loopback health probes do not weaken
  this policy.
- The artifact includes an SPDX 2.3 JSON SBOM and dependency license inventory.
  This is not a legal opinion or penetration test.
- Release CI uses a hash-locked Python build/test toolchain and records the
  artifact's actual source commit/ref kind. It scans tar members and nested
  decompressed wheel members for the documented secret canaries.

## Known limitations

See [Known Limitations](../KNOWN_LIMITATIONS.md). In particular, only
OpenCloudOS has real-host evidence, the artifact is unsigned, Project source is
not backed up by AgentBox, host reboot is untested, and external TLS/remote
access remain operator responsibilities.
