# AgentBox 0.3.0rc27 — visible-client label refresh

Project and Workspace label views now re-read the shared catalog and their
own assignment set every 30 seconds while the page is visible and idle. An
administrator who changes a label in another visible browser session no
longer has to switch focus to see the new state. Each read uses the existing
authenticated, no-store API and exact target/session fences. A background
read keeps the previous values visible but disables writes until its catalog
and assignment snapshots agree. A hidden page, pending write or in-flight
read does not start another poll. On return to the page, the existing
visibility refresh remains the immediate revalidation path.

This adds no subscription daemon, mutation endpoint, cross-host relay,
Runtime access or Secret authority. It provides bounded same-Control-Plane
client convergence; multi-host synchronization remains a separate S08
capability. Python, npm and inert MV3 versions map to `0.3.0rc27`,
`0.3.0-rc.27` and `0.3.0.27`. Validation and exact-head CI evidence are
recorded in [CURRENT_STATE](../project/CURRENT_STATE.md). Node 22 full Web
tests passed 1196 cases; release-version Python tests passed 93. Web
format/lint/typecheck/build and inert MV3 tests/build passed. The isolated
desktop/mobile Chromium matrix passed 112 tests with 28 prescribed skips;
Workspace label screenshots were inspected without overlap or horizontal
overflow. The Web JS bundle was 643.55 kB/182.53 kB gzip, retaining the
prior >500 kB warning. Exact-head CI and merge remain pending. Real-host
and production qualification remain separate.
