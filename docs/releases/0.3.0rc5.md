# AgentBox 0.3.0rc5 — fixed interactive-process development candidate

Planned release display/tag: `v0.3.0-rc.5`. This source increment does not
create a tag, publish a GitHub Release, install a systemd unit/socket, activate
a host, or inherit the real-host qualification recorded for `0.3.0rc1`.

## Included software

- Runtime host manifest v2, exact executable/profile/policy cross-pins and
  descriptor-held one-shot execution authority.
- Three fixed Linux C17 helpers plus the Runtime PTY/WBR transport for Start,
  admission-time attach, output, input, resize, detach, retryable cleanup and
  exact Stop.
- Version-bound auth probes, same-generation local login resume and a shared
  WAW/legacy Claude/Codex conflict coordinator.
- Inert Runtime package templates for tmux, the `waw-sandbox-policies-v1`
  metadata, Claude managed settings, and a canonical exact-two Codex
  requirements/managed-config policy bundle.
- Closed package-data and release-input checks covering the templates, native
  WAW source, and its reviewed build/check scripts.
- A fixed interactive-process document that records profile/digest pinning and
  separates static R10 software from R11 integration and R12 host evidence.
- One version source: Python uses `0.3.0rc5`; root, Web, and browser-extension
  packages use `0.3.0-rc.5`; the MV3 manifest maps this to `0.3.0.5` and the
  extension packager rejects drift; Dashboard derives its visible version from core.

## Verification boundary

The candidate validates process/profile/protocol/Runtime/native source behavior,
static package/release inventories and canonical Codex policy-bundle bytes. It does not establish
an effective Codex configuration: on Unix the documented system requirements
file is `/etc/codex/requirements.toml`, and cloud/legacy managed/MDM layers have
higher precedence. R12 must prove the selected vendor build, placement and
effective values. Linux CI uses fake vendor/attach fixtures to exercise PTY,
tmux, namespace, Landlock/seccomp and cleanup software. It does not run a real
vendor CLI, ship a helper binary, install host policy, handle credentials or
qualify a production host/toolchain.

## Not included

- Host activation, a new or enabled unit/socket, changes to installer lifecycle
  actions, or a real provider/vendor enrollment.
- R11 browser/API controller composition, full encrypted end-to-end failure
  injection, artifact operation rehearsal and full cross-page bilingual UI.
- R12 authorized host evidence for supported vendor builds, official login,
  Project Trust, PTY/isolation/recovery, credential handling, or product
  qualification.
