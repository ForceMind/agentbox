# AgentBox 0.3.0rc11 — Fixed API deployment profile

Source candidate in progress. No tag, GitHub Release, host/client activation,
credential/key operation or new platform qualification is implied.

## Behavior

Production API startup now resolves WAW mode from the fixed, non-secret,
installer-owned `/etc/agentbox/waw-api-profile.v1.json`. The exact parent/file
ownership, modes, links, bounded bytes and canonical two-value profile are
verified. Only a safely absent leaf preserves the legacy disabled default;
unsafe parents, corrupted/replaced files and explicitly injected production
mode fail closed. The profile is revalidated before lifespan startup, and the
console entrypoint reuses the module's installed application and settings.

Factory failure closes a newly created database owner while preserving
caller-supplied services. Existing management routes and test-only composition
remain separate. No environment variable, path selector, HTTP route or key
field is added for choosing WAW mode.

See [the bootstrap contract](../WAW_R12_API_BOOTSTRAP.md). This candidate does
not install the profile or complete the Runtime provider, managed client or
R12 host gates. An enabled profile with missing WAW dependencies still fails
startup. Production remains NOT ADMITTED.

## Version and compatibility

Python `0.3.0rc11`, npm `0.3.0-rc.11`, MV3 `0.3.0.11` retain the unified version
mapping. The version-specific release gate requires all current jobs to succeed
and the two frozen rc8 historical jobs to be skipped. Unknown versions fail.
This source increment has no database schema migration. A supported previous
application can be restored only under the recorded deployment recovery scope;
no Runtime epoch or browser trust floor is rolled back.
